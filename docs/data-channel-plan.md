## 1. 头部账号的共同套路（调研结论）

看的是两类账号：英文的 **Wendover / PolyMatter / RealLifeLore / Economics Explained**（都是无人出镜、
解说 + 图形），中文的 **小 Lin 说**（B 站/YouTube 千万粉级财经）。

共性，按"能不能做成工具功能"排序：

| # | 共同点 | 依据 | 能不能变成功能 |
|---|---|---|---|
| 1 | **自制图表和地图是主画面**，不是配图 | Wendover「custom maps and graphics」、PolyMatter「motion graphics, charts」、Economics Explained「charts combined with narration」 | ✅ 能——这是本次做的 |
| 2 | **数据必须标来源** | 知识类账号的可信度来源；也是平台对财经/医疗类内容的通行要求 | ✅ 能——每张图自带来源角标 |
| 3 | **开场 3–15 秒抛出反差/数字/疑问** | 2026 短视频方法论「前 3 秒抛出核心情绪点或信息点」；完播率是第一权重指标 | ✅ 能——大数字开场卡 |
| 4 | **统一的视觉风格**（同一套配色/字体/版式） | Wendover「clean consistent visual style」 | ✅ 已有 theme，缺"品牌包"管理 |
| 5 | **10–20 分钟、按因果或时间推进、结尾回扣** | Wendover / PolyMatter 的标准结构 | ✅ 结构模板（第 11 节）：三套骨架 + 留存体检 |
| 6 | **说人话 + 比喻 + 故事化**，不堆术语 | 小 Lin 说的核心方法：术语配图表、用比喻讲清楚 | ❌ 这是脚本的事，工具只能提示 |
| 7 | **名词即时解释** | 财经内容的刚需 | ✅ 已有 `Vocab` 组件 |
| 8 | 无人出镜也能做（声音 + 图形） | 四个英文频道全部无人出镜 | ✅ 已有，另有遮脸/换头 |

> 注意第 6 条：**工具解决不了观点和表达**。头部账号真正的护城河是选题和叙述，vidforge 能做的是把
> "有了观点之后"的那段路压到最短。

## 3. 本次已落地：真实数据 → 图表

**新增 `vidforge/data/`**

- `worldbank.py`：世界银行公开数据，**免 key、免注册**，约 1.6 万个指标、200+ 国家/地区。
  结果缓存在 `~/.vidforge/data-cache/`（30 天），所以重渲染不重新联网，老片子也能用当时的数字重建。
  内置常用指标中文名（GDP、人均 GDP、通胀、人口、生育率、老龄化、城镇化、失业、出口占比、FDI、
  政府债务、能源消费、可再生占比、碳排放、互联网普及、军费占比），其余用 `data search` 找。
- `from_csv()`：粘贴表格即可（国家统计局、Wind、自己的表）。自动识别制表符/逗号分隔，
  认得千分位、`—`/`N/A` 空值。
- 数值自动换算成**万亿/亿/万**，图上不会出现 `18270356654533.2`。
- **每个 Series 都带 source**，一路传到图上的角标。

**新增三个 Remotion 组件**（都带来源角标，时长仍然等于这一段旁白的长度）

| 组件 | 用途 | 对应共性 |
|---|---|---|
| `LineChart` | 时间序列，线从左往右随旁白画出来 | #1 |
| `BigNumber` | 一个数字占满屏 + 同比/较某年变化 | #3 |
| `Compare` | 两方并排 + 自动算出"X 倍"并标明谁更高 | #1 |

一个实现细节值得记：折线图的纵轴**不会因为留白而出现负数**——GDP 序列的轴从 -2 开始，
会被读成"曾经是负的"，这是错的。

**入口**

- 命令行：`vidforge data search <词>` / `vidforge data chart …`
- 接口：`GET /api/data/search`、`POST /api/data/chart`
- 界面：第 3 步画面 → 「动画」tab 下方新增「📊 用真实数据做图」：搜指标 → 选国家/年份/图型 →
  取数据（带预览和来源）→ 加入这一段。

## 5. 怎么用

```powershell
# 找指标
vidforge data search 人口
vidforge data search energy

# 直接出图表片段（打印 JSON，便于检查）
vidforge data chart --indicator NY.GDP.MKTP.CD --countries CHN,USA --start 2000 --chart line

# 直接写进项目的某一段
vidforge data chart --indicator SP.POP.TOTL --countries CHN,IND --chart compare --label 中国,印度 `
  --project "$HOME\vidforge-projects\中国历史宇宙" --segment seg3
```

图型选择：
- `line` 看趋势（二十年 GDP、房价指数、人口曲线）
- `bar` 看排名（某一年各国对比）
- `big` 开场钩子（一个数字 + 较某年涨跌）
- `compare` 两方对攻（中美、城乡、十年前后）

自有数据（国家统计局等没有公开接口的）：把表格粘进 `from_csv()`，格式是第一列 x 轴、其余每列一条线：

```
年份,一线城市,二线城市
2021,100,80
2022,92,74
```

## 6. 品牌包（2026-10-01 已落地）

调研结论（决定了设计）：**品牌片头超过约 5 秒会压低 YouTube 的 Intro 指标**（0:30 仍在观看的比例），
而这个指标直接喂推荐；现在主流是**冷开场 + ≤1 秒 logo 闪**。片尾则要 **≥5 秒**，否则 YouTube
的结束画面组件来不及被点。

- `vidforge/brand.py`：品牌配置（名字/slogan/配色/字体/标志/片头片尾开关/音效），
  全局放 `~/.vidforge/brand/brand.json`，项目里的 `brand` 块可逐字段覆盖。
- 三个内置标志（SVG，可直接当头像/角标）：
  - `ticks` 刻度尺 —— 既是图表坐标轴也是时间轴，正好是「数据 + 历史」两半（**推荐**）
  - `line` 上扬折线 + 实心端点
  - `axis` 两轴一点
- `Intro`（1.2 s）/ `Outro`（6 s）两个 Remotion 组件，共用 `Mark.tsx` 把标志画出来。
  片尾右半边**故意留空**：YouTube 的结束画面卡片就放在那里。
- `vidforge brand init|show|preview|sting|slogans`
- **音效自己合成**：`brand sting` 用 ffmpeg 合成三音标识（rise/settle/two）。
  原因是免费 AI 音乐全有许可陷阱（MusicGen 是 CC-BY-NC，变现频道不能用），
  而正弦波没有版权可言。要更丰富的音乐，用 YouTube 音频库 / Pixabay Music / Artlist。
- 构建时自动在片头片尾拼接；**字幕和章节时间轴会整体后移片头的长度**
  （这一条是 e2e 测试抓出来的 bug：不移位的话全片字幕会早 1.2 秒）。

### 推荐方案（可直接用）

| 项 | 建议 | 理由 |
|---|---|---|
| 频道名 | **刻度** | 2 字好记；既是尺子也是标准，直指「量化」这件事 |
| slogan | **把热点放进时间里** | 8 字，同时说清数据和历史两半 |
| 标志 | `ticks` 刻度尺 | 32px 头像上仍然认得出；强调色那一笔 = 「此刻」 |
| 配色 | 深底 `#0d1117` + 米白 `#f3f4f6` + 砖橙 `#d4793a` | 专业冷静，橙色只用于「重点那一笔」，对比度已校验 ≥4.5:1 |
| 片头 | 1.2 s，放在钩子之后 | 超 5 秒掉完播 |
| 片尾 | 6 s，左侧信息右侧留空 | 结束画面可点 |

```powershell
vidforge brand init --name 刻度 --slogan "把热点放进时间里" --en-name KEDU
vidforge brand sting --style rise
vidforge brand preview
```

## 8. 2026-10-02 这一轮：吸引力、速度、启动、体检

### 调研到的、能做成功能的（头部视频通用做法）

| 结论 | 出处 | 我们怎么落地 |
|---|---|---|
| **第一个流失高峰在 25–35 秒** | 留存剪辑方法论 | 片头压到 1.2 秒并放在钩子之后（已做）；下一步在该位置插"图案打断" |
| 前 3 分钟每 10–20 秒换一次画面 | 同上 | 一键配图已按"约每 5 秒一张"配，节奏够密 |
| 动态字幕 / 动效图形提留存 | 同上 | **本轮做了：数字高亮字幕** |
| 章节标记提升会话时长 | 同上 | 已有（YouTube chapters） |

### 本轮新增：数字高亮字幕

旁白里的**数字在被念到的那一刻变色**。这件事只有我们能顺手做——逐词时间戳是 TTS 阶段就有的，
以前只用来断句，没别的地方用。

- `subtitles.write_ass()`：输出 ASS，关键词用品牌强调色，`keywords`（整句里数字始终高亮）
  或 `karaoke`（逐词点亮，念过的数字保持高亮）。`none` 关闭。
- 只有**烧进画面**的那份带高亮；`final.srt` 仍是纯文本，给平台播放器和翻译用。
- 什么算"关键词"：带单位的数字、两位以上的数、小数、年份、金额。单独一个 `1`、`[1]` 不算
  （实测在英文 demo 里会误伤引用角标）。
- 配置：`subtitles.highlight` / `subtitles.highlight_colour`（默认取品牌强调色）。

### 提速（实测数字）

| 改动 | 之前 | 之后 |
|---|---|---|
| **TTS 并行**（edge 4 路 / ElevenLabs 2 路 / VoxCPM 仍串行） | 14 段 26.0s | **7.4s（3.5×）** |
| 烧字幕用硬件编码器（原来写死 libx264） | 89s | 81s |

另外量清楚了一件事：**烧字幕本身就贵**——同一条片子不烧 45s、烧 89s。瓶颈是字幕滤镜而非编码，
所以默认不烧（YouTube 用 `final.srt` 边车字幕更好，还能翻译）；发国内平台再开。

### 一键启动

- 直接敲 `vidforge`（不带子命令）就打开应用。
- **修了一个真 bug**：上次打开的项目被删掉/移走/在没插的盘上时，`vidforge start` 直接崩。
  现在回退到项目选择页。
- 启动失败的提示框只在**没有控制台**时弹（桌面快捷方式用 pythonw）；在终端里改为打印——
  模态框在终端/CI 里会一直等人点，这也是测试挂住的原因。

### UI 流程

- 左侧五步现在**做完的变绿打勾**，判断依据来自项目本身（有没有文本／配音新鲜／每段有画面／
  有没有 final.mp4／有没有上传记录），不是手工标记。
- 每一步底部加**上一步／下一步**，并提示下一步要做什么。之前 React 版只能靠点侧栏跳转。

### 测试

全量套件连跑三遍，**175 个全过**（180s/遍）。过程中发现并修掉的真问题：启动崩溃、模态框阻塞、
数字高亮误伤引用角标。

## 9. 剪映等剪辑软件的常用功能：对照与取舍

**前提**：vidforge 不是时间线剪辑器，也不该变成一个。剪映的价值是"手动精修每一帧"，
这里的价值是"脚本一改，整条片子重出"。所以吸收的是**效果**，不是**时间线交互**。

| 剪映常用功能 | vidforge 现状 | 结论 |
|---|---|---|
| 智能字幕 | ✅ 逐词时间戳，还能按词高亮数字 | 比剪映更准（时间戳来自 TTS，不是识别） |
| 文本朗读 | ✅ edge / ElevenLabs / 自有声音 | — |
| 画中画 | ✅ overlays（图/视频/主持人） | — |
| 转场 | 🟡 原来只有段内「淡入淡出」 | **本轮补：8 种转场 + 段间黑场** |
| 滤镜调色 | ❌ 没有 | **本轮补：统一调色** |
| 比例裁剪（竖版） | ✅ 2026-10-02 做了，见下 | — |
| 自动踩点 | ❌ 没有 | 可做：按 BGM 节拍切图 |
| 关键帧 / 蒙版 / 变速 | ❌ 没有 | **不做**：时长由旁白决定，关键帧要时间线才有意义 |
| 贴纸 / 花字 | ❌ 没有 | **不做**：和「专业、克制」的定位相反 |
| 封面制作 | ✅ thumbnail | — |
| 一键成片模板 | ✅ 分类预设 + 结构模板 | 第 11 节 |

### 本轮补上的

**1. 转场**（原来只有 `fade` 一种，而且只在段内）
- 8 种：淡入淡出、溶解、黑场、白场、左滑、右滑、擦除、圆形打开。
  只挑适合讲解片的；旋转、翻页这类放进去像屏保。
- **段与段之间的黑场**（`segment_fade`）：章节切换最该有一个呼吸点。
  实现上**故意不用 crossfade**——xfade 会把接缝缩短它自己的时长，而本管线的字幕、章节标记、
  片头片尾全部按"实测段长"铺排，缩一点就全错位。改成**在段首段尾原地淡入淡出**，
  观感一样，时长分毫不变（实测：加 0.5 秒黑场后总时长 39.93s → 39.90s，时间轴仍对齐）。

**2. 统一调色**（`look`：film / warm / cool / mono + `look_strength`）
- 为什么需要：一键配图会从 Commons、Openverse、Internet Archive 各取一些，
  色调差别很大，拼在一起像剪贴簿。一条曲线压过去才像同一条片子。
- 强度会被夹在 0–2，手滑打错不会毁画面。

两项都在第 4 步「渲染设置」里。

## 10. 竖版切片（小红书 / 抖音 / Shorts）

一次选题喂两个平台。关键是**不重新渲染**：长视频已经渲好，字幕已经有逐词时间，
`timeline.json` 已经记着每段的起止——所以竖版只是「裁一段 + 换画幅」。

```powershell
vidforge short my-video --list                      # 看有哪些段适合单独成片
vidforge short my-video --segments seg3,seg4        # 按章节切
vidforge short my-video --at 1:30 --seconds 55      # 按时间切
vidforge short my-video --segments seg3 --mode crop --ratio 4:5
```

**两种画幅处理，必须自己选**（16:9 进 9:16 一定会损失点什么）：
- `blur`（默认）整个画面保留，居中放在自身的模糊放大版上。**图表、地图、带坐标轴的东西不会被切掉**——
  这个频道的画面本身常常就是信息。
- `crop` 居中裁满屏。人像好看，但两侧没了，图表会被切。

**字幕**会按切点重新计时、**加大并上移**（手机拇指盖住最下面六分之一），然后烧进去——竖版多半是静音看的。

实现中踩到并修掉的两个：
1. **字幕叠两层**：源文件 `final.mp4` 如果项目开了烧字幕，里面已经有一份小号底部字幕，再烧一份就重叠。
   现在项目开了烧字幕时自动改用 `merged.mp4`（同样的画面，没有字幕）。
2. **字幕不换行溢出**：横版用的 ASS `WrapStyle: 2` 禁止自动换行（横版每行本来就短），
   到 1080 宽的竖版上一句话会冲出两边。竖版改用 `WrapStyle: 0`，字号也从 4.2% 调到 3.4%。

候选片段按**段落**给，不是固定窗口——脚本本来就是按"一个意思一段"切的，一个段落天然是一条短视频。

## 11. 结构模板（钩子-背景-数据-转折-回扣）

完播率是在写稿之前决定的，不在后期。这一节的所有数字都来自留存资料和 YouTube 自己的指标定义：

- 第一个大的流失点在 **25–35 秒**——这里还在清喉咙，刚吸引来的人就走了；
- YouTube 的 **Intro** 指标就是 0:30 还在看的比例，它会反过来影响推荐；
- 前三分钟里画面应该每 **10–20 秒**变一次；
- 六分钟以上加章节能提高会话时长。

所以模板不是写作风格，而是**一串带时长配额的段落**，排法保证「承诺」在 0:30 之前落地、
「回报」是摊开给的而不是攒到最后。

三套骨架（`vidforge/structure.py`）：

| id | 名字 | 适合 |
|---|---|---|
| `data_explainer` | 钩子-为什么现在讲-背景-数据-转折-回扣 | 经济、房地产、人口、能源 |
| `history_explainer` | 场景-谜题-来龙去脉-转折-照到今天-下一期 | 历史、国际、政策 |
| `news_take` | 发生了什么-为什么现在-数字-两种解读-我的判断 | 政策、金融、科技快评 |

```powershell
vidforge structure list                                   # 三套骨架
vidforge structure outline --template data_explainer --minutes 10
vidforge structure prompt --minutes 10                    # 喂给 AI 的那一段
vidforge structure check my-video                         # 体检现有脚本
```

**一块不等于一段**。10 分钟的「数据」块有三分钟，一段三分钟正好是体检会报警的东西，
所以每块按 30 秒拆成若干段落——骨架自己必须能通过自己的体检，这一条写成了测试
（`test_the_skeleton_passes_its_own_retention_check`，三套骨架 × 六种时长）。

**钩子有上限**。share 固定时，20 分钟的视频钩子会变成 72 秒，那就不是钩子了。
`Beat.max_seconds` 把它压在 15 秒，省下的秒数按 share 摊回其他块，总时长不变。

**体检的五条规则**（`check()`，渲染过就用 `timeline.json` 的真实时长，没渲染过按字数估）：

1. 开场既没具体数字也没提问题 → `problem`
2. 第一段超过 24 秒 → 钩子被稀释
3. 一段从钩子一直讲到 35 秒以后 → `problem`，流失最高的位置没有换气
4. 任何段落超过 45 秒 / 前 30 秒只有一段 / 六分钟以上没章节名
5. 结尾没有回到开场那个数字

跑在真实项目「中国历史宇宙」（23 段）上，报出 seg1 开场 41 秒穿过流失窗口，以及 10 个 45 秒以上的段落。

写这一节时被自己的测试抓到两个 bug：

1. **`聊一聊` 被当成数字**。`_NUMBER` 原来匹配 `[一二三四五六七八九十...]`，
   于是「今天我们来聊一聊房地产」这种纯寒暄开场能通过第 1 条规则。现在要求是数字、量级（百千万亿）、
   两个以上连写的汉字数字，或汉字数字紧跟单位（十年、三倍、三成）。
2. **短片的骨架比片长还长**。`news_take` 的 `min_seconds` 之和是 105 秒，1 分钟的片子会得到 105 秒的骨架。
   现在装不下时按比例缩所有下限。
3. 「25–35 秒没换气」原来会把**任何**跨过窗口的段落都报出来，连骨架自己都过不了。
   真正的失败是**从钩子就开始、到 35 秒还在讲**的那一段——改成这个条件后，骨架干净了，
   而真实项目的 seg1 照样被抓住。

UI 在「1 脚本」步骤里：选骨架 → 表格显示每块的时长/字数/段数/要做到什么 →
生成脚本时自动把骨架附到提示词后面（提示词文本由后端 `prompt_block()` 生成，
CLI、提示词、体检三者不会各自漂移）；旁边一个「给现在的脚本做留存体检」。
手写稿的人可以点「写成空段落」，直接把骨架写成带章节名的空段落（会先确认再覆盖）。

## 12. 选题：做什么会火，怎么抓热点

### 12.1 先分清两件事

vidforge 现在只做了**后面那半**：

| | 问题 | 现状 |
|---|---|---|
| **发现** | 现在什么在火？我该做什么？ | ❌ **完全没有** |
| **验证** | 这个选题值不值得做？怎么差异化？ | ✅ `research/` 已经做得不错 |

验证那半已经挺好用：输入一个选题 → 查 YouTube 同类视频的播放/时长/频道数
（有 `YOUTUBE_API_KEY` 走 Data API，没有就解析公开搜索页，两条路都不用登录）→
把这张表喂给 AI，要回一个 JSON：做 / 换角度 / 别做、饱和度、**5 个标题、3 个开场钩子、
别人都没覆盖的空白**。

缺的是上游：**它不会告诉你今天该查哪个选题。**

### 12.2 实测：哪些热点源能不带 key 抓到

我在这台机器上一条条试过（2026-10-05）：

| 源 | 结果 | 怎么拿 |
|---|---|---|
| **今日头条热榜** | ✅ **50 条**，JSON 直接可用 | `GET toutiao.com/hot-event/hot-board/?origin=toutiao_pc` |
| **百度热搜** | ✅ **52 条** | `GET top.baidu.com/board?tab=realtime`，正则取 `"query":"..."` |
| **Google News RSS** | ✅ **每查询 100 条** | `news.google.com/rss/search?q=<词>&hl=zh-CN&gl=CN&ceid=CN:zh-Hans` |
| Google News 头条 RSS | ✅ | `news.google.com/rss?hl=zh-CN&gl=CN&ceid=CN:zh-Hans` |
| **Google Trends RSS** | ✅ `geo=AU` 可以 | `trends.google.com/trending/rss?geo=AU`。⚠ **`geo=CN` 返回 400**，Google Trends 没有中国区 |
| Hacker News | ✅ | 官方 Firebase API，免费无 key（科技选题用） |
| YouTube 频道 RSS | ✅ | `youtube.com/feeds/videos.xml?channel_id=<id>`，盯对标账号出了什么新片 |
| ~~微博热搜~~ | ❌ | `s.weibo.com/top/summary` 返回 200 但是**登录墙**，解析出 0 条 |
| ~~知乎热榜~~ | ❌ | API 401 |
| ~~Reddit~~ | ❌ | `.json` 端点 **403 Blocked**，连换浏览器 UA 也不行（现在要 OAuth） |

**结论**：中文热点靠 **头条热榜 + 百度热搜**，深度文章靠 **Google News RSS 按关键词查**，
海外/科技补 **HN + Google Trends(AU)**，对标账号靠 **YouTube 频道 RSS**。
都是公开端点、都不要 key、都符合「不加云依赖」这条原则。

### 12.3 光有热榜不够：热榜和这个频道的匹配度

热榜上大部分词跟「用数据看热点，用历史看今天」没关系（娱乐、体育、社会新闻）。
所以抓回来之后需要**打分**，而不是直接列出来。可用的信号，全都是本地能算的：

1. **领域匹配**：命中「经济｜房地产｜人口｜金融｜历史｜科技｜能源｜国际｜政策」的词
   —— 用 `categories[].topic_notes` 里已有的词表，不用新建配置。
2. **有没有数字可讲**：标题里有数字/百分比/年份 → 能配图表 → 适合这个频道。
   `structure._NUMBER` 那个正则可以直接复用。
3. **有没有历史可照**：能不能找到一个「上一次发生」——这是频道的后半句，
   也是别人做不了的差异点。
4. **饱和度**：直接喂给已有的 `research.search()`，看 YouTube 上有多少人做过、
   近 12 个月的中位播放。**这一步是现成的**，只是现在要手动触发。
5. **禁用词过滤**：`categories[].banned_keywords` 已经有了，直接套上。

打完分，前几名再走第 4 步（已有的 research 验证），就串成了一条完整的链：

```
热榜/RSS  →  领域+数字+历史 打分  →  前 N 名走 research 验证  →  选定  →  结构模板  →  写稿
  12.2          12.3                      已有                       已有(第11节)
```

### 12.4 什么内容会火：从已有的数据里看，而不是猜

`research.summarize()` 已经在算这些了，只是没人把它当选题指南用：

- `recent_median_views` 比 `median_views` **高**：这个题材正在变热，值得追。
- `recent_12m` 很少但 `median_views` 很高：**老题材没人更新**，这是最好的机会——
  老视频还在吃流量说明需求在，没人做新的说明没人跟你抢。
- `long_form_share` 低而你做长视频：差异化。反之说明观众在这个题材上要长内容。
- `channels` 少而 `max_views` 高：少数几个号垄断，进去难；
  `channels` 多而中位播放不低：分散，好进。

这几条判断比「什么内容会火」的泛泛规则靠谱得多，因为它是**你这个选题的实际数据**。

### 12.5 建议做法

加一个「热点」页（P1，优先级在地图组件之前）：

- 后端 `vidforge/trends/` — 一个源一个文件（`toutiao.py`、`baidu.py`、`googlenews.py`、
  `hn.py`、`ytfeed.py`），每个只做「抓回来 → 统一成 `Topic(title, source, url, heat, when)`」。
  复用 `assets.cached_search` 做缓存（**热榜 15 分钟缓存就够**，别把人家服务器当自己的）。
- `score.py` — 12.3 那五条信号，纯本地计算。
- 界面：一张按分数排序的表，每行一个「查一下」按钮直接跳到现成的 research 验证，
  一个「用这个建项目」按钮直接带着标题进第 1 步。
- **礼貌**：带正常 UA、串行请求、尊重缓存。这是读公开页面，不是爬站。

## 13. 钩子、再钩、以及让人关注点赞

### 13.1 第一时间不被划走：钩子的 4 个硬规则

数字来自留存资料和 YouTube 自己的指标定义，已经写进 [`structure.py`](../vidforge/structure.py) 的常量：

| 规则 | 常量 | 为什么 |
|---|---|---|
| **问题必须在 15 秒内落地** | `HOOK_SECONDS = 15` | 观众在这 15 秒里决定走不走 |
| **开场必须有具体数字或一个问题** | `check()` 规则 1 | 「今天我们来聊一聊房地产」是纯寒暄，等于放弃 |
| **不要自我介绍，不要铺垫** | 骨架里的 `hook.role` | 自我介绍是给已经关注你的人看的，而划走的人还不认识你 |
| **第一段不超过 24 秒** | `check()` 规则 2 | 超了就是钩子被稀释 |

**软件已经在做的**：
- `structure.prompt_block()` 把这几条**写进提示词**，让 AI 一开始就按这个写；
- `check()` 事后体检，`HOOK_SECONDS` 没落地会报 `problem`；
- `research/analyze.py` 的 JSON schema 里有 `hooks: ["3 opening lines for the first 15 seconds"]`
  —— **调研那一步就已经帮你生成了三个开场句**，而且是看过同类爆款之后生成的。

实测跑在你的「中国历史宇宙」上：`seg1 开场 41 秒`，直接被判「钩子被稀释」。

**三种实际好用的开场形式**（按这个频道的定位排）：

1. **反直觉的数字**：「去年有 680 万平方米新房没卖掉——但房价没跌。」
   数字 + 矛盾，两样都在第一句里。
2. **把结论先说了**：「这期视频的结论是：降息救不了房地产。接下来 10 分钟我证明给你看。」
   观众知道自己要听什么，就不会走。
3. **一个具体场景**（历史题材）：「1816 年 6 月，瑞士的湖面结了冰。」
   具体的时间地点人物，像电影开场——这是 `history_explainer` 骨架的 `scene` 这一块。

### 13.2 多久再钩一次

| 时间点 | 要发生什么 | 常量 |
|---|---|---|
| **0–15s** | 问题落地 | `HOOK_SECONDS` |
| **25–35s** | **流失最高的位置**，必须有新信息或一次转折，不能还在铺垫 | `DROPOFF_START/END` |
| **0:30** | YouTube 的 **Intro 指标**就是这一刻还在看的比例，它直接影响推荐 | `INTRO_METRIC_AT` |
| **前 3 分钟每 10–20s** | 画面要变一次 | 段落驱动画面，所以靠段落长度控制 |
| **任何段落 ≤ 45s** | 超过就是一段没有切换点的长坡 | `MAX_SEGMENT_SECONDS` |
| **新稿按 30s/段规划** | 留出写超的余量 | `SEGMENT_TARGET_SECONDS` |
| **>6 分钟** | 加章节名（实测能提高会话时长） | `CHAPTER_MIN_MINUTES` |

**体检的规则 3 是专门盯 25–35 秒这个窗口的**，而且写法很讲究：它不报「任何跨过窗口的段落」
（那样连骨架自己都过不了），只报**从钩子就开始、到 35 秒还在讲**的那一段——
也就是「观众进来之后一直没有新东西」这个真实的失败。

**所以「再钩」在这个软件里不是一个功能，是一组约束**：
骨架把时长配额分好 → 每块拆成 ≤30 秒的段落 → 段落边界就是画面切换点 →
25–35 秒自然落在一个新段落里。

### 13.3 让人关注、点赞 —— 这是目前的空白

**已经有的**：
- 片尾 6 秒卡（`Brand.outro_seconds = 6.0`，≥5 秒才够人点订阅）
- 片尾文案 `Brand.subscribe = "订阅，下期继续"`
- `Brand.next_hint` 那句「下期：…」
- 骨架最后一块 `callback.role` 要求「最后一句引出下一期」

**完全没有的**：**视频中途任何形式的 CTA**。没有中段角标、没有点赞提示、没有订阅动画。
`remotion/` 的 10 个组件里没有一个是干这个的。

**建议补的（按性价比）**：

1. **中段角标**（最值钱）：一个 Remotion 小组件，在第 2–3 分钟某段右下角浮现 3 秒
   「订阅 · 用数据看热点」。放这里是因为：能看到 2 分钟的人已经被内容说服了，
   转化率远高于片头，而片头放 CTA 反而是在赶人走。
2. **「这个数字你猜到了吗」式的评论引导**：不要「记得点赞关注」这种话术，
   要**一个具体的问题**放在转折之后——这个频道的观众是来跟你争论的，给他们一个争论点。
   可以做成骨架 `turn` 这一块的一条可选要求。
3. **回扣里顺带要一次点赞**：`callback` 已经要求回到开场那个数字，
   在给出结论之后那一句是最自然的位置（观众刚获得了一个结论，正是最愿意点的时候）。
4. **片尾卡加一个「下期预告画面」**：现在只有文字 `next_hint`，
   加一张图会明显提高「看下一个」的比例。

**不建议做的**：片头 CTA、全程角标、「三连」话术。
这个频道卖的是可信度，叫卖会直接扣信任分——而信任是这个定位唯一的护城河。

### 13.4 一张时间轴

```
0s ──── 15s ──────── 30s ──────── 2~3min ──────── 结尾 ──── +6s
 │       │            │              │              │         │
 数字/   问题已        Intro          中段 CTA        回扣      片尾卡
 问题    经落地        指标           角标 3s         + 点赞    订阅/下期
 开场                 ↑              （待做）        （待做）  （已有）
         ↑            每 10~20s 换画面
         25~35s 必须有新信息或转折（体检规则 3 在盯）
```

能自动检查的部分已经在 `vidforge structure check` 里了；CTA 那两格是待做项。
