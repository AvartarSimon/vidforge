# 六帽十轮循环记录 — vidforge v0.2 → v0.3

日期：2026-09-17 · 基线：v0.2（a64bf57，MTTW 方案 A/B/C 落地后）· 目标：功能更丰富、更智能，30 分钟视频稳定出片，画面流畅清晰。
每轮 = 一个帽子视角 → 发现 → 改动 → 验证。白=事实/度量，红=用户感受，黑=找问题，黄=放大优点，绿=创新，蓝=流程/结构。

| 轮 | 帽 | 发现 | 改动 | 验证 |
|---|---|---|---|---|
| 1 | ⚪ 白 | 没有任何长视频数据 | `tools/stress.py` 生成 40 段/30 分钟合成项目（静音 TTS、含竖图与视频切片） | run 1：28.7 min 视频 **258 s**（QSV + 并行），1.03 GB / 4.8 Mbps，986 条字幕，时间轴漂移 90 ms |
| 2 | ⚫ 黑 | ① 时间轴按"计划时长"累加，AAC 21 ms 帧粒度 × 40 段会漂；② `-stream_loop` 对 `-ss` 后的切片循环回文件头；③ edge-tts 单次失败中断 40 段；④ 超长单段撞 ElevenLabs 5000 字上限；⑤ 长 id 撞 Windows 路径长度 | ① 渲染后 ffprobe 实际时长；② 先渲切片再循环；③ 3 次退避重试；④ >2500 字符警告；⑤ id 截 60 | run 2 漂移 **21 ms**；单测 `test_slice_loop…` |
| 3 | 🟢 绿 | 配画面是最耗时的手工步骤；章节感弱；不同段音量不一致；整段贴入的长段落太长 | ✨ 一键自动配图（关键词 → 搜索片段）；`auto_title_cards`（每章 3 s 标题卡）；旁白 `loudnorm` -16 LUFS；拆段按句子 ~50 词 | e2e 抓到 loudnorm 对**纯静音**产生 NaN → 加 `volumedetect` 守卫 + 单测 |
| 4 | 🔴 红 | 渲 30 分钟只见日志滚动，不知道等多久；每次都从第 1 步开始 | 进度条：阶段 + n/N 段 + 预计剩余；首次打开落到第一个未完成步骤 | 截图核对 |
| 5 | 🟡 黄 | 故事板+挑选器是核心，但"改一段 → 看效果"要等全片 | 「预览这一段」草稿单段渲染；「复制一段」 | API 复用 render_segment，几秒出结果 |
| 6 | 🔵 蓝 | `build()` 120 行；进度靠解析日志文本 | 拆成 `_stage_tts / title_cards / assets / remotion / render / assemble`，`_Ctx` 传递；`pipeline.progress()` 结构化上报，UI 不再猜 | 44 测试全绿 |
| 7 | ⚪ 白 | 复测 | — | run 2：配音缓存后 **159 s** 出 28.7 min；漂移 21 ms；文件 1.05 GB |
| 8 | ⚫ 黑 | ① HEIC/损坏文件到渲染才报错；② Windows 下浏览器占用 `final.mp4` 时重渲失败；③ `pause_after` 负数 | ① 上传时 PIL/ffprobe 校验并给中文提示；② 写临时文件 + `os.replace` 重试；③ 校验 | 单测 ×2 |
| 9 | 🟢 绿 | 运镜线性，机械感；静帧经双三次缩放偏软；字幕在复杂画面上难读 | smoothstep 缓动；成片质量加轻微 `unsharp`；字幕"半透明底框"样式 | 渲染测试通过；见下截图 |
